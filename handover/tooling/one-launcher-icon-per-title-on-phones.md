# One launcher icon per title on phones

2026-10-20, maintainer question. Nothing is built; this records what each platform allows and the
chosen direction. Android manifest is generated by `scripts/build-apk.sh`, iOS bundle by
`scripts/build-ios-app.sh`; neither has a per-title entry point today.

## Open

- Android can show one icon per title from a single APK: `<activity-alias>` entries targeting the
  one `NativeActivity`, each with its own `android:label`, `android:icon` and `LAUNCHER`
  intent-filter. No Java needed. The main activity would lose its own `LAUNCHER` filter.
- The native side has to learn which alias launched it. An alias cannot pass extras, so read
  `getIntent().getComponent().getClassName()` over JNI from the activity handle `android-activity`
  gives us, and map it to the title selection `--title` uses; unknown falls back to the picker.
  Needs a device (the S24) to verify.
- Per-title icons must be our own art (no game content in the APK), the fallback layer. The
  leakage audit allows exactly the five `ic_launcher.png` paths, so it must learn the new names.
- Separate aliases share one process and storage dir; set `android:taskAffinity` per alias if
  launching a second title should not reuse the first title's task.
- iOS has no `activity-alias`: one bundle, one home-screen icon. Options: (1) one `.app` per
  title with its own bundle id (the only true separate icons; free Apple IDs allow 3 sideloaded
  apps, so five titles need a paid account, and each bundle carries its own binary); (2)
  alternate app icons (`setAlternateIconName`) swap the single icon, show a system alert, and
  do not give several at once; (3) Home Screen quick actions (`UIApplicationShortcutItem`), a
  long-press menu that hands the chosen title in the launch options; (4) an in-app launcher.
- Decided 2026-10-20: the maintainer has no paid Apple developer account. Per-title iOS bundles
  are out (a free Apple ID sideloads 3 apps at once, 7-day re-sign); iOS gets the in-app
  launcher plus quick actions in the one bundle.

## Next Steps

1. Chosen direction: a touch-friendly in-app launcher as the cross-platform baseline - a title
   picker of large tiles (one per installed title, our own art, pointer/touch first per the
   new-screens rule), shown at boot when no title is preselected. This is the only piece iOS and
   Android share, and it costs no platform work.
2. Android: generate `activity-alias` entries and per-title icons in `scripts/build-apk.sh`,
   widen the leakage allowlist, then the JNI alias read (about an hour for manifest and icons,
   the JNI read is the part needing a device).
3. iOS: add quick actions on top of the launcher (single bundle). Per-title bundles are not
   planned; revisit only if a paid account appears.
