# The PS2's engine flare plays and reads as nothing on screen

2026-08-12. `WO_SHIP_ENGINEFLARE` is wired, attaches per craft, and **is** drawing (the nozzle glow changes with `psys::ColourScale`) - a maintainer just sees only the trail ribbon. The asset side is closed: both engine-flare textures are on the PS2 archive after all, under the declared name with the extension rewritten to `.pct` (`Engine_noise` 64x64 8bpp, `grabbedEngineFlare128x64x8` 128x64 8bpp) - a name-lookup gap, not an asset gap. See [texture-names.md](../docs/ghidra/functions/ps2-pulse-eu/texture-names.md). **The related boost-plume half is closed**: [The PS2 boost plume draws, and the PS2 file is not the PSP file wearing the same name](the-ps2-boost-plume-draws-and-the-ps2.md), dated 2026-08-23. Both are render-side, neither touches the simulation.

**2026-09-03: both remaining questions answered with real frame captures, and the thread is closing.**

**On our own build**: `just play ps2 --race --mode time_trial --hold cross --ticks 340 --screenshot t.png` (headless, no window - `--screenshot` never opens one) against the same command with `--hold cross` left out. `COUNTDOWN_TICKS = 272` (`crates/race/src/state.rs`) gates thrust at the start line, so 340 ticks is enough to actually be moving in the held-thrust capture (213 km/h) and stationary in the other. The nozzle glow is unmistakably different between the two, not merely "the trail ribbon" as the original note read it: a wide white/violet halo at rest, a small pink/magenta core once under thrust and moving. Confirmed directly, trivially reproducible with the commands above.

**On the real PS2 build**: the PCSX2 harness built for the boost-plume thread (`docs/reverse-engineering/pcsx2-debugger.md`, dated 2026-08-23) was not yet usable this session - `~/.config/PCSX2/bios` was empty, so `just pcsx2-boot` failed at `ReportErrorAsync: Startup Error: PCSX2 requires a PlayStation 2 BIOS`, a precondition the doc page assumed rather than stated (now fixed there). With a PAL BIOS placed in that folder, the harness booted straight to `SCES-54748` in 3 s and the documented front-end walk (autosave -> 50 Hz prompt -> title -> name/tag entry -> format card -> save -> Race Campaign -> Grid 1 -> Single Race, Moa Therma White, Venom, 3 laps -> Assegai) reproduced exactly as the doc's table describes it, at every one of the fourteen steps, on the first attempt. A savestate was taken on the grid (`just pcsx2-state save 2`), so a capture from here on is one command (`just pcsx2-frame out.png <frames> cross --from-state 2`), not the four-minute walk. **The real disc draws the same shape of effect**: a bright core at the nozzle with a magenta/pink streak below it, present stationary on the grid and growing into a longer, brighter white-cored trail at 305 km/h under thrust - `exhaust.rs`'s own reading ("sizes it from an intensity that ramps with thrust and a speed term") is visibly true of the original, not only of this project's reproduction. Confidence 70: one capture, one savestate, a qualitative colour/shape match rather than a pixel or hex-value comparison against our own render - the exact palette and the size-vs-speed curve are not measured against each other, only that both are present and both react.

Neither capture is committed - both are derived evidence and gitignored, per the standing rule; the commands above reproduce them from a clean checkout (plus, for the PCSX2 half, the harness's own BIOS precondition).

## Open

- No quantitative match between our render's flare and the real PS2's has been made - exact colour, alpha ramp, and the size-vs-speed curve are unmeasured against each other. Only that both draw a comparable effect that visibly reacts to thrust and speed is shown.
