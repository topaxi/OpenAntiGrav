# Reversed grids were putting craft off the track; fixed by walking the spline instead of extrapolating a straight line

2026-08-19. `oag_gameplay::grid_pose`'s straight-line offset from the anchor was only ever live-verified against one *forward* grid (Talon's Junction). A sweep of every Wipeout HD circuit's grid (`crates/game/tests/hd_trackwall_ground_truth.rs::every_hd_grid_lands_on_the_track`, both directions, opponents on) found 9 of 12 **reversed** grids put one or more of the eight slots off the collision mesh entirely - up to 145 units from the driveable line on `tech_de_ra`'s reversed grid - because a reversed grid sits on whatever piece of track its own `Start Position` node landed on, which is far more often a curve than the authored front straight a forward grid sits on, and a straight line run for the grid's 138-unit span walks off a curve. `oag_game::race::spawn::grid_poses` now walks the track's own resampled spline from the anchor instead, keeping both measured constants (`GRID_ROW_PITCH`, `GRID_COLUMN_OFFSET`) and the anchor's own heading for every slot - only the position derivation changed. Two traps found and closed on the way: an early version crossed spline *path* boundaries (`Spline`'s table concatenates paths in file order, and consecutive indices are only spatially adjacent within one path - see `ai_order`'s own doc comment on `05_Track`), which made several previously-clean *forward* grids worse; and a second version inferred "ran off the end of the path" from a fixed distance tolerance against the walked target, which false-triggered on tracks with coarser sample spacing and silently fell back to the broken straight line on slots that had plenty of path left - replaced with an explicit boundary flag from the walk itself. Closes 8 of 9 broken reversed grids; `modesto_heights`'s reversed grid still has one slot without collision within the probe's reach (21.42 units off the line, inside the track's own half-width - not chased further, recorded as a named exception in the regression test). `our_grid_is_the_originals_grid` (the one live-captured comparison this project has) still passes at its original 3-unit tolerance afterward. **Found and left alone**: relocating exactly where `05_Track`'s opponent first meets trouble (that circuit already has 134 racing-line samples with no collision under them, per `docs/gameplay/ai.md`) moved it onto a spot where the craft gets wedged bouncing rather than sitting still - position frozen for thousands of ticks, speed oscillating 0.2-10 units/s, never sustained below `STALL_SPEED` long enough to trip the rescue's three-term stall test. That is a separate, pre-existing gap in the rescue predicate (it catches sustained low speed, not bounce-in-place), not something this fix caused or fixed; `stall_rescue_ground_truth.rs::a_craft_that_stops_on_the_disc_is_put_back` is left failing rather than adjusted to hide it. See [grid.md](../docs/ghidra/functions/psp-pulse-usa/grid.md#reversed-grids-the-straight-line-ran-off-the-curve).
