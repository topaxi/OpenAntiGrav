# Is HD's language picker ever *shown*, or only entered?

2026-09-05, and it is what is left after HD's boot chain became a measurement. Three cold boots on RPCS3 walked all eight steps of `oag_hd::frontend::BOOT_CHAIN` in the order `skin.xml` declares, so `BOOT` is `oag_title::Provenance::Measured` and [ADR-0025](../docs/architecture/adr/0025-a-boot-chain-carries-its-provenance.md)'s "an emulator capture now *upgrades* a title" has happened - see [hd-frontend.md](../docs/formats/hd-frontend.md#the-boot-chain-declared-and-then-watched) for the transcript, timings and the two things it deliberately does not claim. **This thread is one of those two.** `TTY.log` names `Language Selection` being entered on every boot, which settles the *state machine*; it says nothing about whether a frame of the picker is ever put in front of a player. The PS3 takes its system language from the XMB and the screen's own `LanguageAutoRedirect` is a sufficient mechanism for entering and leaving it inside a single frame, and `RPCS3.log` shows the English language plugin already loaded before the picker is entered, which is consistent with exactly that. **No frame of it has ever been caught.** cold-02's 1.5-second film runs `Sony Computer Entertainment presents` (11.77 s) -> black (14.97 s) -> the Studio Liverpool reel already playing (20.01 s), and the picker is somewhere in that gap. **The absence is not evidence**, which is the whole reason this is a thread rather than a finding: a root-window grab costs 1.5-3 s on its own, so a screen up for less than that falls between two frames whether or not it drew, and `TTY.log` cannot arbitrate because it flushes in bursts - five transitions arrived on one poll in both captures ([rpcs3-debugger.md](../docs/reverse-engineering/rpcs3-debugger.md#it-flushes-in-bursts-so-a-timestamp-on-a-switching-screen-line-is-not-the-transitions)). The question matters beyond tidiness: if the picker never presents, then this build drawing it on a boot is drawing a screen the original skips, and the difference is invisible in a chain comparison because the *state* really is entered either way.

## Open

- Does `Language Selection` ever present a frame on a PS3 whose XMB language matches one of the sixteen plugins? Unanswered; the boot chain's order around it is measured (85) and this is not.
- If it does not present, what makes it not present - `LanguageAutoRedirect` firing on the XMB language, or the screen being entered and left before any draw? These are different mechanisms and only the second would generalise to a machine whose XMB language has no plugin.
- Would a PS3 set to a language HD does *not* ship (there are sixteen plugins, not every XMB language) stop at the picker? That is the case where the screen has something to ask, and it has never been tried.

## Next Steps

- Capture at a rate that can resolve a sub-second screen. RPCS3's own frame recorder (`just rpcs3-record`, `Session.take_screenshot`) writes the framebuffer rather than the root window and does not pay the 1.5-3 s `import` cost; a recording across the first 25 seconds of a cold boot would settle it where a film of stills cannot. Note that `record` is currently pointed at the driven part of a race, so this is a change to what it covers, not a new tool.
- Cheaper and worth doing first: change RPCS3's configured system language to one HD ships no plugin for, boot, and see whether `TTY.log` still leaves `Language Selection` in the same frame. A picker that stops there under one setting and not another is the mechanism, and it needs no frame capture at all.
- Do **not** answer this by reading `skin.xml` harder. `LanguageAutoRedirect` is declared and its firing condition is not; the declaration is where the ambiguity comes from.
