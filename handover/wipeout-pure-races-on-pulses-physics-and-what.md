# Wipeout Pure races, on Pulse's physics, and what is still absent is a list of unrecovered entry names

2026-08-12, branch `pure-to-race`. `just play <pure disc> --race` loads and drives; `crates/game/tests/pure_race_ground_truth.rs` and `crates/pure/tests/collision_classes_ground_truth.rs` pin it against both pressings. **Recovered on the way**: `.vex` v4 floor `0x36b` and wall `0x36c` (confidence 88, by a facing statistic calibrated on Pulse - `docs/formats/collision.md`); the font roles, which are read off the language plugins now rather than named (`oag_game::language::roles`); `<pitch>` optional with `PITCH_STAND_IN`. **Most of that list closed on 2026-08-13** by the class-name table index (`crates/pure/tests/class_table_ground_truth.rs`, confidence 94): `reset_collision` `0x37f`, `start_position` `0x36e`, `speedup_pad` `0x36f`, `weapon_pad` `0x370`, `engine_flare` `0x371`, `skycube` `0x378`, `section` `0x37b`, `ship_collision_fx` `0x382`. **The `Cage` reading of `0x37f` was wrong** - Pure authors reset as a continuous under-road surface (99.9 % of the spline at ~10.7 below) where Pulse authors patches, which is why the facing statistic matched no Pulse `Reset`; `reset_zone_ground_truth::pures_reset_surface_respawns_the_ship_too` flies a craft into it and it respawns. **`V4`'s class-id gaps closed 2026-09-03**: `airbrake` `0x377` and `anim_transform` `0x372` by the same table index, checked against real files for the first time (six of Pure's eight team ships for the former, all 16 circuits for the latter); `lod_group` `0x2de` and `fogcube` `0x385`, neither in the class-name run, by the same kind of node-shape evidence that pinned `mesh`/`transform` - see `docs/formats/pure-status.md` and each field's own comment in `crates/formats/src/vex/classes.rs`. **The only `V4` fields still `None` are `mag_floor_collision`, `cage_collision` and `track_wall_collision`, and all three are findings, not gaps**: Pure authors no magstrip, no cage, and no HD-only trackside barrier, on any circuit. **This finding is triple-chained**, which is the thing worth trusting about it: facing statistic (88) for floor and wall, class-name run index (94) for all three, and Pulse's independently disassembled `vex::CLASS_NAMES` reproducing the same gap structure - `0x3b9 + 19 + 1 = 0x3cd` is Pulse's own reset. **Do not repeat the claim that ten of the fifteen anchors are independent of that disassembly** - `exhaust.md` says ten IDs *of that ~55-entry table* predate it and names two, `0x3e6` and `0x3e7`, neither of which is an anchor here. The overlap is unestablished; what holds is that all fifteen were in `vex.rs` before the string run was searched for.

**The entry-name list closed on 2026-09-06**, and both of its two remaining rows turned out to be findings rather than spellings:

- **Pure's Zone hull was never unrecovered after 2026-08-19** - the thread simply lagged the code by three weeks. `crates/pure/src/race::ZONE_TEAM` has spelled it `Zone_01` since then, read off the disc's own `<PI_Team name="Zone_01"><Values type="Zone" location="Data\Ships\Zone_01">`, and `DEFAULTS` has consumed it through `oag_title::ZoneCraft::OwnShip` for just as long. Re-verified 2026-09-06 against `Data\Plugins\PI001\Definition.xml`: `Zone_01` is the only one of eleven `<PI_Team>` entries marked `type="Zone"`, the other ten including a `Zone` that is `type="Race" multiplayer="true"` - the unlockable livery, exactly as `ZONE_TEAM`'s own doc comment already said. **No change was needed and none was made.** The earlier probe of the literal name `Zone` missed because Pure spells the Zone craft as a *team directory*, not as a per-team `Zone.vex` the way Pulse does.
- **Pure's boost plume has no entry name because Pure ships no boost-plume asset.** `crates/pure/src/race::ships`' own docs used to say "Pure certainly has one, and what it calls that file is unread" - an assumption carried from Pulse, now retracted. Four probes across three sources, each with a Pulse positive control beside it: no path template of that shape (Pulse's `%s\%sboost.vex` at `0x08a84ccc` has no counterpart, and the whole 3.6 MiB executable holds two `boost` strings, neither a path); no archive entry under any of the eleven declared locations on either pressing; and no `boost_flare` anchor node in any Pure hull where every Pulse hull carries two. Confidence 93. See `docs/ghidra/functions/psp-pure-usa/ship-models.md`.

**Four per-craft model names came out of the same block** and were not being looked for at all - `%s\Shipwreck.vex`, `%s\Phantom.vex`, `%s\Phantom_shipwreck.vex`, `%s\VR\Ship.vex`, contiguous with `%s\Ship.vex` at `0x08a7a5d4`..`0x08a7a61c` inside `Ship.cpp`'s string run. Confidence 96, and self-certifying: each blob carries its own `Z:/Data/Ships/<Team>/<Leaf>.mb` back. They are in `crates/pure/src/race::ships` with the full hit matrix pinned by `crates/pure/tests/ship_models_ground_truth.rs` (3/3 against both discs). **`Phantom` is the top speed-class rung getting its own model**, which no other title in this lineage does.

Its HUD atlas (it has none - the HUD is `.vex` models off `Data\HUD\*.vex`, a whole second HUD path), its loading-screen wave and tips (it ships neither), are resolved findings, not gaps.

## Open

- The overlap between the fifteen triple-chained anchors and `exhaust.md`'s ten pre-existing IDs is unestablished.
- **What selects `Phantom.vex`** - the name and the eight-team hit matrix are measured, the trigger is not. Nothing should be wired to a speed-class comparison on the strength of the name alone.
- **What `VR` is.** The prefix names a whole alternate presentation set (`Data\Weapons\vr_bomb.vex`, `Data\Tex\vr_env.tga`, `Data\Tex\EngineFlare\vr_engine_noise.mip`, a per-team `VR\Textures\`), on ten of the eleven locations. No path that selects it has been read.
- **Whether Pure's boost is visually inert.** The asset is absent; the effect need not be. Pure carries `grabbedEngineFlare128x64x8.mip` exactly as Pulse does, so a boost that brightens the existing `engine_flare` billboard in code would leave nothing for any of the four probes above to find. The flare's draw path is unread on Pure.
- **`Data\Psys\WO_SHIP_ENGINEFLARE.POB` resolves to nothing**, on either pressing, while all 26 `Data\Psys\WO_*.POB` literals the binary itself lists do. `Data\Ships\Feisar\Ship.vex` (and its two Phantom siblings) name it in a `Name` attribute and no other team's hull does. Authoring leftover or a name the code rewrites - unread.
