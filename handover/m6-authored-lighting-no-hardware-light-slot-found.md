# M6 authored lighting: no hardware light slot found enabled

`AmbientLight`/`DirectionalLight` are registered, `PointLight` genuinely is not, and none of the mesh-draw functions read so far enables a GE light slot. The runtime direction vector recovered along the way is useful evidence for [`lighting.md`](../docs/formats/lighting.md)'s open rotation-versus-translation question. `FUN_08a6b5bc`/`FUN_08a6b5c8` are World/Scene container class stubs, not lighting classes themselves - but `FUN_08a6b5bc` specifically is the class key that identifies the world object, so it is load-bearing for this question, not a dead end (correcting an earlier note on the page). A fourth pass (2026-08-31) closed off `World_LoadTrack_q`'s own body as `DirectionalLight`'s consumer - disassembly-verified, not just decompiled - and found its name is doubtful (it's called as a generic small object constructor, not handed "the world"); it also hit, and cross-referenced, an already-documented `jal` relocation wart on a second binary. A fifth pass, same day, decompiled `Race_CreateModeObject` and confirmed `FUN_08886950`'s own `param_1` is one hop short of the world object (`*(param_1+8)` reaches it), definitively ruling out `FUN_08886950` too. Full account on [`psp-pulse-eu/lighting.md`](../docs/ghidra/functions/psp-pulse-eu/lighting.md).

## Open

- No GE light slot has been found enabled by any mesh-draw function read so far
- `lighting.md`'s open rotation-versus-translation question for the runtime direction vector is still unresolved
- `DirectionalLight`'s final consumer (a reader of `world+0x40`/`+0x7c` after `World_CollectMarkerLists` populates them) is still unfound after five passes; both `World_LoadTrack_q` and `FUN_08886950` are now definitively ruled out (neither ever resolves the world pointer, let alone reads past it) - the remaining candidates are whatever calls `FUN_08a6b5bc` (the world object's own class key) besides the two functions already read, or a later per-frame function reached some other way
- `World_LoadTrack_q`'s own name is doubtful: it's called from `FUN_08886950` as a generic 60-byte object constructor, not literally handed "the world" - no replacement is anywhere near the 50-confidence floor to act on, so it stays unrenamed and open
