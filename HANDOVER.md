# Handover

State that is **not** inferrable from the repository itself. Formats, decisions and the plan live in [`docs/`](docs/README.md); open work lives in [`handover/`](handover/), one file per thread, in `rendering/`, `gameplay/`, `frontend/`, `tooling/` or `audio/`. This file is the index plus what a fresh reader would otherwise rediscover.

**Keep it that way.** A finding belongs on a docs page with evidence and a confidence score; an open thread in `handover/`; this file points at both. Rewrite a section in place rather than appending a dated pass: `git log -- HANDOVER.md` is the history.

## Read this first

- **Status per title:** [`docs/overview/status.md`](docs/overview/status.md) (built vs. read vs. verified).
- **The disc images are in `data/images/`** (Pulse PSP USA/EU and PS2 EU, Pure PSP USA/EU, HD PS3 EU, 2048 and Omega packages with patches); hashes in [`source-images.md`](docs/reverse-engineering/source-images.md). Sessions have believed them lost and verified nothing: `/bin/ls -la data/images/` before concluding a ground-truth test "cannot run". `rg`/`fd` return nothing under `data/` and a spawned agent's worktree has no `data/` (use `--no-ignore`, `just link-data`; CLAUDE.md "Data and images"). Plain `ls` may be aliased (`ls -la` failing with `command not found: -la` is not a broken argument).
- **Derived evidence under `data/` (`data/traces/`, `data/shots/`, `data/cache/`) is not durable; the committed `verification/scenarios/*.inputs` and scripts that regenerate it are.** A 2026-07-29 pass found reference traces gone while docs and `wall.rs` cited them. A test that needs a capture prints the regenerating command and returns early without `OAG_REQUIRE_GAME_DATA=1`. `data/traces/` is currently populated here; `ls` it rather than trusting this line. `talons-junction-time-trial-lap.csv` and `-omega.csv` are different files.
- **Four suite numbers look green and are not; read all four before believing any red count** (one mistake, trusted without the check that asks "did the thing I think I measured run"):
  1. **A truncated run reads as a better tree and hides what follows**: `just test-data` must run with `--no-fail-fast` (the `justfile` does; a 2026-09-02 run stopped at 138 of 3,300 after two early `oag-formats` reds).
  2. **`0 skipped` is not evidence any data was exercised**: nextest counts a test that early-returns on a missing file as passed.
  3. **A filter can select a different set than you meant and report a confident green.** `-E 'test(...)'` matches a test's name and module path, not its binary: `test(race_finish)` selected one unrelated passing test, and a "re-run of the failures" came back 39 of 39 green. Re-run a ground-truth failure with `test(/^race_finish_ground_truth::/)` (module path) and keep `--run-ignored all` (without it an exact-name filter reports `0 tests run: 0 passed` as success). **Run `cargo nextest list` on the filter before trusting the run.**
  4. **A red count means nothing without the variable's state attached**: the same tree gave 6 failed plain and 17 failed under `OAG_REQUIRE_GAME_DATA=1` (the extra reds were missing captures and DLC packs turned from silent passes into failures). Always say which one a number means.
- **There is no inherited red in `test-data`.** Do not hand a member "expect one inherited failure". A red ground-truth test usually encodes a real disagreement: understand why before making it green. Two 2026-09-02 reds were premise expiry (a test whose assumption stopped being true after a verified improvement): the disc gives a destroyed craft "Ship destroyed" instead of a place (`0x08a82dfc`, 75), so `race_finish_ground_truth` branches on which ending happened; `ace` opponents now shoot each other, so `difficulty_ground_truth` prints wrecks instead of asserting none. **Still open, not closed**: the bounce-in-place stall (a craft frozen near one point with speed flicking 0-13 never trips the dwell counter, e.g. `05_Track` novice; `docs/ghidra/functions/psp-pulse-usa/grid.md`); `stall_rescue_ground_truth` is scoped to the sustained-stall claim that holds, and the dwell counter is pinned by `crates/raceplay/src/tests/respawn.rs::a_stopped_opponent_is_flagged_after_the_dwell`.
- **A red that moves with load, passes alone and resists diagnosis is a shared-path race before it is a starvation story**: two `ps2_source_ground_truth` transcode tests shared one scratch directory and nextest's parallelism raced them (four investigations; `transcode_scratch`'s doc comment). `oag-disc::ground_truth listing_matches_chdman_and_the_reference_iso` extracts a PSP ISO into `/tmp/oag-ground-truth.iso`; a full `/tmp` tmpfs fails it as `chdman extractdvd failed`, which reads like a bad invocation. Free `/tmp`; do not hunt a disc bug.
- **Do not "simplify" `Cargo.toml`'s per-crate `opt-level` lines or `.config/nextest.toml`'s priorities**: the lines look redundant next to the `"*"` glob (`[profile.dev.package."*"]` never matched a workspace member) and the priorities look cosmetic, and together they are worth most of the suite's speed ([workspace-layout.md](docs/architecture/workspace-layout.md#build-profiles)). `just test-data` runs `scripts/check-test-budget.py` over its own log; when it fires, re-profile the tail (CLAUDE.md "The test-data suite").
- **Check `git status` before assuming the tree is clean** (a milestone once sat uncommitted for a day). Re-measure gate counts rather than trusting a number in a file.
- **Rendering fidelity gaps are mostly not bugs**: bloom, grading and several authored light classes are tracked on the roadmap; do not guess-fix from a screenshot. Two counter-examples of the other kind, where the disc authored it and nothing read it:
  - **The light rig.** HD authors a sun direction, sun colour and ambient in `track.envsettings` ([`envsettings.md`](docs/formats/envsettings.md)); `mesh.wgsl`'s two invented directions were a stand-in. Traps: `"Lighting.Sky colour"=128 128 128 0` is a byte quadruple (only the missing decimal point says so), and `Sun direction` is not a unit vector on most circuits (four degenerate). Magnitudes are authored for a linear HDR pipeline with a tonemapper, so hue is drawn and scale is not; that is evidence ADR-0020's gamma-authoritative model is wrong *for HD*, recorded on the page and not acted on until a running-original reference frame exists.
  - **The vertex attribute declaration.** A chunk's `+0x58` points at a declaration giving stride, and per attribute a `~crc32` name, RSX type and byte offset; the texture coordinate was being read from the last four bytes, which on the commonest layout is `lightmapUV` (HD's Talon's Junction smeared into streaks, 2026-08-18; `docs/formats/rcsmodel.md`). **Trap**: `+0x58` is the index count on a `LAYOUT_INLINE` chunk, so a disc-wide sweep that does not gate on the `+0x06` layout byte returns convincing noise. **Lesson**: a sweep run against labels a heuristic produced cannot find the field one word away; when a heuristic stands in for a missing field, check the field is missing.

## Open threads

One file per thread under [`handover/`](handover/), in `rendering/`, `gameplay/`, `frontend/`, `tooling/` or `audio/`, whichever its subject fits best. **The index is the files' own frontmatter, not a list here.** Every thread opens with:

```yaml
---
status: ready-to-wire   # ready-to-wire | re-first | measure | blocked-maintainer | blocked-hardware | parked
titles: [pulse, hd]     # from pulse, pure, hd, 2048, omega; or [all]
updated: 2026-10-26     # newest date in the file
summary: "One line, at most 150 characters, saying what is OPEN, not what landed."
categories: [rendering] # optional: extra categories on top of the directory
---
```

- **ready-to-wire**: the RE is done; what is left is wiring or building.
- **re-first**: a recovered law, field or trigger is still missing.
- **measure**: needs a capture, a live read or a run to settle a number.
- **blocked-maintainer**: waits on the maintainer's decision, review or listen.
- **blocked-hardware**: the next step needs a device or a machine beyond the workstation (Steam Deck, S24, a Mac, iOS, a second monitor); a lane runs it when the maintainer offers the device.
- **parked**: nothing scoped; revisit on demand.

List them with `just threads [--status S] [--title T] [--category C]` (`--counts` prints the tally). "What is ready to wire for Pulse?" is `just threads --status ready-to-wire --title pulse`. `just check-handover` refuses a thread with missing or invalid frontmatter, a status outside the set, or a summary over 150 characters.

## Working rules that were learned expensively

Most live in `docs/`: [reverse engineering](docs/reverse-engineering/methodology.md#rules-learned-the-expensive-way), [reading a capture](docs/reverse-engineering/verification-protocol.md#reading-a-capture-rules-that-each-cost-a-session), [GhidraMCP bridge quirks](docs/reverse-engineering/toolchain.md#search_instructionss-mnemonic-filter-is-exact-match-not-substring) (`search_instructions`'s `mnemonic` filter is exact-match, so a sweep silently misses underscore-prefixed delay-slot forms) and [measuring a renderer change](docs/rendering/README.md#measuring-a-renderer-change).

What stays here concerns working in *this* repository with other writers in it:

- **Editing this file or a `handover/` thread**: verify each cut against the page or evidence it cites before cutting. Compress or delete a thread that is closed or stale, never one still carrying open work. Never merge numbers into a total that does not already appear merged on its source page.
- **`git stash push -- <pathspec>` captures a file's entire working-tree diff, not just your hunks** (2026-08-25: it swept another session's uncommitted `menu.rs` refactor off disk, recoverable only from the stash commit's blob). Before stashing a file another session may touch, `git diff -- <path>` and check the whole diff is yours; otherwise use a worktree or message them. (Members never stash at all; `member-rules.md`.)
- **Do not run `just` or `cargo fmt --all` while anything else is editing**: a mid-edit gate reports failures that do not exist and `fmt --all` rewrites files another writer holds open. Scope to `-p <crate>`.
- **Commit a doc two parties are editing promptly**: concurrent uncommitted edits look like data loss to whoever looks second.
- **Split a large file as one map from the original applied in a single pass**, not carved interactively (each edit shifts the line numbers below it; `crates/game/src/main.rs`, 4,808 to 430 lines, 2026-08-16). `impl` blocks private-to-file become `pub(crate)` once pieces are siblings, not `pub`.
- **If two sessions run at once, the value is their disagreement, not their throughput.** On 2026-08-09 every number in four commits was reproduced by whoever did not produce it, and each caught refuted citations the other missed; a spawned subagent went idle four times and produced nothing. Split by *claim* and re-derive each other's numbers; do not split by directory and trust the reports. Not an argument for more agents.

## Traps that are live

- **`--features native-video` makes the boot fifty times slower and `just play` turns it on** (Linux, `justfile:25`): 4.9 s of boot against 0.08 s on `pulse-psp-eu.chd` with warm caches, because `GstDecoder::open` decodes every frame into memory (~288 MiB for the two reels) where the AV1 cache path decodes on demand ([ADR-0017](docs/architecture/adr/0017-gstreamer-native-video.md) chose that, costed at 270 frames/53 MiB for the backdrop; the boot prints its own timings). A lazy GStreamer path is not done.
- **Two things convert into `data/cache/movies` and must never overlap**: the boot's two reels and the `--prefetch` worker both shell out to `ffmpeg`, and two processes writing one cache file corrupt it. `Session::start_prefetch` serialises them; `--refresh-video` with `--prefetch` re-converts the boot's reels too (wasteful, still ordered).
- **A display gate keyed on "is there data" reads "nobody reported" and "nothing to report" as the same thing**: the loading bar vanished on ordinary boots because the media phase reported no counts (fixed 2026-08-12 with `boot::MediaPlan::loads` and `boot::MediaWorker::progress`; the bar is continuous and must stay monotonic; [frontend boot](docs/architecture/frontend-boot.md#loading-is-not-transcoding)).
- **A success check that asks "did this produce a picture?" cannot see that the side effect the caller wanted did not happen**: `--prefetch` on a `native-video` build wrote no cache file (GStreamer decodes into memory) yet reported converted, relisting the same 22 movies each run. `prefetch::convert` sets `movie::Decode::prefer_cache` unconditionally.
- **An existing AV1 cache file beats the platform decoder with no flag** (`open_psmf` asks `movie::cached` first; ADR-0017's default still holds for the uncached case, and ADRs are immutable, so making the uncached default the cache needs a new one). Measured on `pulse-psp-eu.chd`: 4.80 s of media phase through GStreamer, 36.08 s once to build the cache, 0.06 s after. `--prefer-av1-cache` builds it for the boot's reels, `--prefetch` for all 22, `--refresh-video` implies it.

**The Ghidra bridge's `switch_program` can silently no-op, and its reply says success** (2026-08-19). Four binaries share the display name `BOOT.BIN` (`psp-pulse-usa`, `psp-pulse-eu`, `psp-pure-usa`, `psp-pure-eu`); `rename_function_by_address` and `create_function` ignore the `program` field and act on the truly active program (unlike `get_function_by_address`). The failure is silent cross-binary corruption: a `just apply-names` for `psp-pulse-eu` wrote its names onto `psp-pulse-usa` (234 stray names, cleaned 2026-08-19). `scripts/apply-ghidra-names.py` and `scripts/audit-ghidra-names.py --prune` now re-read the true active program after a switch and abort loudly. **Correction 2026-09-03: the "collision" was not a bridge limit.** `psp-pure-usa` and `psp-pure-eu` simply were not open in the tool (`list_instances` reports the project's files; `list_open_programs` reports what the tool has open); one `open_program` each fixed it, and `psp-pulse-eu` applied all 301 rows with no help. **Check `list_open_programs` before believing a program is unreachable.** All four `BOOT.BIN`s were confirmed live and clean on 2026-09-03.

**A duplicate address in `names.tsv` silently broke `just apply-names` for `psp-pulse-usa` from 2026-09-02** (`plasma.md` re-documented `WeaponStats_ParseTurbo`/`ParseAutopilot`, already owned by `weapon-stats.md`; `apply_group` refuses the whole group on the first duplicate, "duplicate address 0x0880c92c"). `check-ghidra-names.py` has a `check_duplicates` rule now, so it trips offline.

**`psp-pulse-usa`'s Ghidra DB stores every static address pre-relocation, so `get_xrefs_to` and `get_function_callers` return "none" for almost all `jal` targets** (found 2026-08-11, re-derived 2026-08-19; cost most of a session). Static `jal` bytes hold the unrelocated `R_MIPS_26` field: `target = image_base + ((word & 0x03FFFFFF) << 2)` with image base `0x08804000` (`get_current_program_info`), no `(addr+4) & 0xF0000000` term. An xref tool saying "no callers" is therefore not evidence: `search_instructions` on the zero-padded *relative* operand (`jal 0x000645cc`, not `jal 0x0886a5cc`). [contact-response.md](docs/ghidra/functions/psp-pulse-usa/contact-response.md#its-call-target-needed-the-image-base-added-by-hand---ghidras-own-bytes-are-pre-relocation). **It is every `jal`, not regional** (2026-08-27: zero of 524,728 instructions display a relocated target; an earlier claim of two exempt ranges was retracted, [weapon-fire.md](docs/ghidra/functions/psp-pulse-usa/weapon-fire.md#read-this-first-the-disassemblys-addresses-are-image-base-relative)). Whether this is a PSP-ELF trait or this project's importer is open; `psp-pulse-eu` has it too (`World_CollectMarkerLists` `0x0887a1c4` shows as `func_0x000761c4`, [lighting.md](docs/ghidra/functions/psp-pulse-eu/lighting.md#a-fourth-pass-world_loadtracks-own-body-is-now-disassembly-verified-to-hold-no-consumer-and-its-name-is-doubtful)), which leans towards the importer.

**The same pre-relocation values are in `lui`/`lw` HI16/LO16 pairs and raw 32-bit data words, and the base is per segment.** Any address-shaped value read off this program's static bytes (not surfaced by a working xref) is a pre-relocation candidate; `get_xrefs_to` on the naive value reports nothing, which reads as "no reference". There are **two `PT_LOAD` segments and exactly two bases**: `.data` (segment 0, `VirtAddr 0`) gets `+0x08804000`; `.cplinit`/`.linkonce.d`/`.ctors`/`.bss` (segment 1, `VirtAddr 0x002d5798`) gets `0x08ad9798`. The `.rel.text` `r_info` bits 16-23 are the segment index (`jal` targets are always segment 0). A resolution that lands inside a real function when a global was expected is the tell of the wrong base ([anim-transform.md](docs/ghidra/functions/psp-pulse-usa/anim-transform.md#the-second-relocation-base-is-found-it-is-per-segment-not-per-image)). **Stop doing the arithmetic by hand: `scripts/psp-relocate.py` replays the PRX relocation records** (reproduces five independently recorded addresses; 97.85% of 108,813 targets land in a loaded segment; `xrefs` on the relocated value; `member` for base-plus-offset globals; [workflow.md](docs/ghidra/workflow.md#stop-doing-it-by-hand-scriptspsp-relocatepy)). A "third base" `+0x08ad9450` proposed on 2026-09-05 was a misread (the base was built by `addiu ?,?,-0x7378` and the naive value was `0x00058c88`; three cross-checks agreed because one constant slip of `0x348` was cancelled by an invented base); `DAT_08b32428` is `DAT_08b32420 + 8` with no record of its own, and this binary never uses `$gp` as a base (0 of 521,965 instructions). The two write sites in [missile.md](docs/ghidra/functions/psp-pulse-usa/missile.md) were `0x134` low and are corrected.

**Finding references despite the pre-relocation DB:**
- `get_xrefs_to` on the *naive* address works for a `lui`/`lw` data reference (`0x002ac818` returned all 27 `g_ingame` sites where the relocated `0x08ab0818` returned none) but not for a `jal` (`get_function_callers("InGame_Construct")` stayed empty).
- **A `.rodata` string reference has no working xref at all**: `%s\ship_eliminator.dat` (`0x08a7ff7c`), `%s\Ship.vex` (`0x08a7ba64`) and `Data\Psys\%s.POB` (`0x08a884dc`) all come back empty on both forms, so no path template here has a working xref and an empty result proves nothing. Calibrate against a string whose consumer is known.
- **Check the naive address against the section table**: `.text` below `0x272a3c`, `.rodata` `0x274000`-`0x2ac5e4`, `.data` from `0x2ac600` in `psp-pulse-usa`. `0x08a884dc - 0x08804000 = 0x002844dc`; borrowing a digit gives `0x000844dc`, inside `.text`, and a confident empty result on an address that never could have matched.
- **Scan the ELF outside Ghidra** (quick): `BOOT.BIN` is a PRX (`e_type` `0xff80`), `.text` at file offset `0x80`, virtual `0x0`, length `0x272a3c` (read the section headers). Walk four bytes at a time keeping each `lui`'s immediate per register; when an `addiu`/`ori` completes a pair, compare against `<target> - 0x08804000`. A `jal` target is `(word & 0x03ffffff) << 2`, already naive, so comparing with `<function> - 0x08804000` yields the caller list. Seconds of script against a long failed search in Ghidra: reach for it as soon as one `get_xrefs_to` is empty.

## Verification status: what to lean on

**The disc chooser was driven end to end on this machine** (2026-08-18; no automated way): `just launch` listed every image under `data/images/` with title, platform and serial read off each disc, `hdfury-ps3-eu.iso` came up red and unselectable beside the decrypted twin it shares a serial with, and two Down presses plus Return booted `pure-psp-eu.chd` (survey of seven images: 0.85 s). **To repeat it**: input must go over X11 (`unset WAYLAND_DISPLAY`; `xdotool` cannot reach a Wayland window and `xdotool key --window` does not work, so focus the window and use plain `xdotool key`). **Xvfb is no substitute**: Mesa reports "No DRI3 support detected - required for presentation" and nothing is drawn or ticked. A headless capture cannot reach it either (see the chooser row in "Scope decisions").

**The cross-platform determinism gate runs four layers** (2026-08-15): CI's `determinism` job runs `oag-core`, `oag-physics`, `oag-gameplay` and an `oag-ai` scenario on Linux, Windows and macOS, release and debug. The AI one exists because the physics gate drives scripted input, so no controller decision was ever hashed: `oag_ai::Line::curvature` called the platform `acos` from day one and nothing failed (the two implementations differ on 8.6 % of the domain by up to one ULP; it calls `oag_core::math::acos` now). [determinism.md](docs/architecture/determinism.md#each-gate-covers-the-layer-below-it-and-one-thing-more) lists what is still uncovered.
