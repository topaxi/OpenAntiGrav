# Handover

State that is **not** inferrable from the repository itself. Formats, decisions and the plan live in [`docs/`](docs/README.md); open work lives in [`handover/`](handover/), one file per thread, in `rendering/`, `gameplay/`, `frontend/`, `tooling/` or `audio/`. This file is the index plus what a fresh reader would otherwise rediscover.

**Keep it that way.** A finding belongs on a docs page with evidence and a confidence score; an open thread in `handover/`; this file points at both. Rewrite a section in place rather than appending a dated pass: `git log -- HANDOVER.md` is the history.

## Read this first

- **Status per title:** [`docs/overview/status.md`](docs/overview/status.md) (built vs. read vs. verified).
- **The disc images are in `data/images/`** (Pulse PSP USA/EU and PS2 EU, Pure PSP USA/EU, HD PS3 EU, 2048 and Omega packages with patches); hashes in [`source-images.md`](docs/reverse-engineering/source-images.md). Sessions have believed them lost unverified: `/bin/ls -la data/images/` before concluding a ground-truth test "cannot run" (CLAUDE.md "Data and images"). Plain `ls` may be aliased (`ls -la` failing with `command not found: -la` is not a broken argument).
- **Derived evidence under `data/` (`data/traces/`, `data/shots/`, `data/cache/`) is not durable; the committed `verification/scenarios/*.inputs` and the scripts that regenerate it are.** A test that needs a capture prints the regenerating command and returns early without `OAG_REQUIRE_GAME_DATA=1`; `ls data/traces/` rather than trusting a doc. `talons-junction-time-trial-lap.csv` and `-omega.csv` are different files.
- **Four suite numbers look green and are not; read all four before believing any red count:**
  1. **A truncated run reads as a better tree**: `just test-data` must run with `--no-fail-fast` (the `justfile` does).
  2. **`0 skipped` is not evidence any data was exercised**: nextest counts a test that early-returns on a missing file as passed.
  3. **A filter can select a different set than you meant and report a confident green.** `-E 'test(...)'` matches a test's name and module path, not its binary (`test(race_finish)` selected one unrelated test; a "re-run of the failures" came back 39 of 39 green). Re-run a ground-truth failure with `test(/^race_finish_ground_truth::/)` and `--run-ignored all` (without it an exact-name filter reports `0 tests run: 0 passed` as success). **Run `cargo nextest list` on the filter first.**
  4. **A red count means nothing without the variable's state attached**: the same tree gave 6 failed plain and 17 under `OAG_REQUIRE_GAME_DATA=1`. Always say which one a number means.
- **There is no inherited red in `test-data`.** Do not hand a member "expect one inherited failure": a red ground-truth test usually encodes a real disagreement, or a premise that expired after a verified improvement (a destroyed craft gets "Ship destroyed" instead of a place, so `race_finish_ground_truth` branches on the ending; `ace` opponents shoot each other, so `difficulty_ground_truth` prints wrecks). **Still open**: the bounce-in-place stall (speed flicking 0-13 never trips the dwell counter, e.g. `05_Track` novice; `docs/ghidra/functions/psp-pulse-usa/grid.md`); `stall_rescue_ground_truth` is scoped to the sustained-stall claim, and the dwell counter is pinned by `crates/raceplay/src/tests/respawn.rs::a_stopped_opponent_is_flagged_after_the_dwell`.
- **A red that moves with load and passes alone is a shared-path race before it is a starvation story** (two `ps2_source_ground_truth` tests shared one scratch directory). `oag-disc::ground_truth listing_matches_chdman_and_the_reference_iso` extracts a PSP ISO under `target/tmp`: a full disk fails it as `chdman extractdvd failed`. Free space; do not hunt a disc bug. **Nothing in tests or scripts writes `/tmp`** (a `tmpfs` with a per-user quota): `oag_testdata::scratch` in Rust, `scripts/oag_tmp.py` / `oag-tmp.sh` in scripts, held by `just check-temp-use`.
- **Do not "simplify" `Cargo.toml`'s per-crate `opt-level` lines or `.config/nextest.toml`'s priorities**: they look redundant next to the `"*"` glob (which never matched a workspace member), and together they are worth most of the suite's speed ([workspace-layout.md](docs/architecture/workspace-layout.md#build-profiles)). When `scripts/check-test-budget.py` fires, re-profile the tail (CLAUDE.md "The test-data suite").
- **Check `git status` before assuming the tree is clean.** Re-measure gate counts rather than trusting a number in a file.
- **Rendering fidelity gaps are mostly not bugs**: bloom, grading and several authored light classes are tracked on the roadmap; do not guess-fix from a screenshot. Two counter-examples, where the disc authored it and nothing read it: **the light rig** (HD's `track.envsettings` authors sun direction, colour and ambient where `mesh.wgsl` had two invented directions; magnitudes are authored for a linear HDR pipeline, evidence ADR-0020's gamma-authoritative model is wrong *for HD*, not acted on until a running-original reference frame exists: [`envsettings.md`](docs/formats/envsettings.md)), and **the vertex attribute declaration** (a chunk's `+0x58` declares stride and per-attribute name, type and offset; the texture coordinate was read from the last four bytes, `lightmapUV` on the commonest layout; **`+0x58` is the index count on a `LAYOUT_INLINE` chunk**, so a sweep not gated on the `+0x06` layout byte returns convincing noise: `docs/formats/rcsmodel.md`). **Lesson**: a sweep run against labels a heuristic produced cannot find the field one word away; check the field is really missing.

## Open threads

One file per thread under [`handover/`](handover/), in `rendering/`, `gameplay/`, `frontend/`, `tooling/` or `audio/`, whichever its subject fits best. **The index is the files' own frontmatter, not a list here.** Every thread opens with:

```yaml
---
status: ready-to-wire   # ready-to-wire | re-first | measure | blocked-maintainer | blocked-hardware | parked
titles: [pulse, hd]     # from pulse, pure, hd, 2048, omega; or [all]
updated: 2026-10-26     # newest date in the file
summary: "One line, at most 150 characters, saying what is OPEN, not what landed."
categories: [rendering] # optional: extra categories on top of the directory
size: M (70)            # optional: XS | S | M | L | XL, effort for one member; (confidence 0-100) optional
difficulty: medium (50) # optional: easy | medium | hard, how settled the path is; (confidence 0-100) optional
kind: debt              # optional: debt = something already built that has to be paid back
---
```

- **ready-to-wire**: the RE is done; what is left is wiring or building. **re-first**: a recovered law, field or trigger is still missing. **measure**: needs a capture, a live read or a run to settle a number. **blocked-maintainer**: waits on the maintainer's decision, review or listen. **blocked-hardware**: needs a device beyond the workstation (Steam Deck, S24, a Mac, iOS, a second monitor); a lane runs it when the maintainer offers one. **parked**: nothing scoped; revisit on demand.
- `size` (XS under an hour, S a few hours, M half a day, L a day, XL more than a day: split the thread) and `difficulty` (easy: steps known; medium: a few unknowns; hard: an unread law, a design question or a likely negative result) are optional; leave them out rather than guess. The number in parentheses is your confidence on the [rubric](docs/reverse-engineering/confidence-rubric.md)'s 0-100 scale; an estimate inferred rather than stated carries a low one. **kind: debt** marks paying back something already in the tree (a shortcut, workaround, stand-in or frozen ratchet list), not new work.

List them with `just threads [--status S] [--title T] [--category C] [--size Z] [--difficulty D] [--kind debt]` (`--counts` prints the tally); `just debt` prints every ratchet's frozen baseline plus every `kind: debt` thread. `just check-handover` refuses a thread with missing or invalid frontmatter, a value outside its set, or a summary over 150 characters.

**A new thread needs its frontmatter, not an index line.** When a thread's work lands, delete its file; there is no second place to edit. Task numbers in a title are the ones the agent passes used, kept because commits and docs cite them.

**Do not cite a `handover/*.md` thread from anywhere outside `handover/` and this file.** A thread file is deleted the moment its work lands, so a citation from a doc comment, script or test dangles silently (`scripts/check-doc-links.py` only checks `docs/**/*.md`). State the fact directly, or point at the `docs/` page that carries it.

## Working rules that were learned expensively

Most live in `docs/`: [reverse engineering](docs/reverse-engineering/methodology.md#rules-learned-the-expensive-way), [reading a capture](docs/reverse-engineering/verification-protocol.md#reading-a-capture-rules-that-each-cost-a-session), [GhidraMCP bridge quirks](docs/reverse-engineering/toolchain.md#search_instructionss-mnemonic-filter-is-exact-match-not-substring) (`search_instructions`'s `mnemonic` filter is exact-match, so a sweep silently misses underscore-prefixed delay-slot forms) and [measuring a renderer change](docs/rendering/README.md#measuring-a-renderer-change). What stays here concerns working in *this* repository with other writers in it:

- **Editing this file or a `handover/` thread**: verify each cut against the page or evidence it cites before cutting. Compress or delete a thread that is closed or stale, never one still carrying open work. Never merge numbers into a total that does not already appear merged on its source page.
- **`git stash push -- <pathspec>` captures a file's entire working-tree diff, not just your hunks** (it once swept another session's uncommitted refactor off disk). Before stashing a file another session may touch, `git diff -- <path>` and check the whole diff is yours; otherwise use a worktree. Members never stash (`member-rules.md`).
- **Do not run `just` or `cargo fmt --all` while anything else is editing**: a mid-edit gate reports failures that do not exist and `fmt --all` rewrites files another writer holds open. Scope to `-p <crate>`. **Commit a doc two parties are editing promptly.**
- **Split a large file as one map from the original applied in a single pass**, not carved interactively (each edit shifts the line numbers below it). `impl` blocks private-to-file become `pub(crate)` once pieces are siblings, not `pub`.
- **If two sessions run at once, the value is their disagreement, not their throughput**: every number in four commits was reproduced by whoever did not produce it (2026-08-09), and each caught refuted citations the other missed. Split by *claim* and re-derive each other's numbers; do not split by directory and trust the reports.

## Traps that are live

**`ps4-omega-eu`: the tagged-object constructor idiom** (vtable install, `.cpp`-tag write to `param_1[0xb]`, callback to `param_1[1]`, context-list registration walk) **is boilerplate every class uses, not evidence a candidate matches a sibling-binary class** (a `Collision.cpp` candidate was byte-identical to all thirteen branches of `ModeManager_ConstructByMode`; [`weapons.md`](docs/ghidra/functions/ps4-omega-eu/weapons.md), [`collision.md`](docs/ghidra/functions/ps4-omega-eu/collision.md)). A `.cpp` tag match needs class-specific evidence (a field offset, enum, magic number, or a loop count times stride equal to a separately computed allocation size).

**Every static negative on `ps3-hdfury-eu`'s `EBOOT.elf` recorded before 2026-09-15 09:29 is stale**: stock Ghidra could not decode the Cell `lvlx` instruction (851 sites in 294 functions) and the program was reimported ([toolchain.md#ps3](docs/reverse-engineering/toolchain.md#ps3)). Re-run any undated or earlier "no writer / no caller / no xref" before trusting it; load-bearing ones are marked `**[stale 2026-09-15: ...]**` inline, the rest are unaudited.

**`cargo check` does not link an executable**: a `--screenshot` run after only a `cargo check` runs the old binary (two before/after pairs came back zero pixels different, and a draw-time `wgpu` validation panic never showed). A change to `render.rs` or any `.wgsl` needs a real `cargo build` plus a capture.

**Adding a weapon to `oag_weapons::pickup::IMPLEMENTED` re-rolls every statistic downstream of `pickup::draw`**, so a race-wide behaviour statistic can go red with nothing it measures touched. **Check the sample size before hunting a bug.** The maintainer's ruling: make the sample discriminate (`race::Options::seed` is the resampling axis); weakening the bound and re-baselining were both rejected (`ram_ground_truth`'s `RACES` went 6 to 40). **When a ground-truth bound goes red, check the denominator before the numerator.**

**A `Data\Psys\<NAME>.POB` string search in HD's executable finds weapon and debug effects and is blind to continuous/ambient ones** (46 of 82 names; no environment name is among them). Re-establish a control for each new *category* of name before trusting a zero-hit search (`docs/formats/pob.md`, HD corpus).

**A count kept in prose drifts in every copy** (`RACE_EFFECTS` grew 8 to 15 while prose said 7 and 11): recompute from `RACE_EFFECTS.len()`.

**A tuning number chosen on the twelve lone-craft circuits can turn a *field* ground-truth test red while `just` stays green** (`oag_ai::Tuning::curvature_span` = 10 broke `lap_times_ground_truth::every_opponent_that_laps_has_a_lap_time`; `crates/raceplay/tests/ai_span_sweep.rs` reports both boards). **Run `just test-data` after any AI tuning, start-line or grid-timing change**: `just` never runs `#[ignore]`d disc-backed tests.

**A breakpoint-driven PPSSPP capture burns wall-clock far faster than emulated time, and the attract-demo idle timer (about 120 s) runs on wall-clock**: a capture can roll into the demo mid-run. Walk to the state and start capturing in one process, and budget by wall time since the last input ([ppsspp-debugger.md](docs/reverse-engineering/ppsspp-debugger.md)).

**`ghidra-mcp` bridge traps** ([workflow.md](docs/ghidra/workflow.md#bridge-quirks-that-have-each-cost-a-session)): it is one shared instance and `switch_program` moves a global pointer any session shares, so **pass `program` on every mutating call** and re-verify with an explicit-`program` read (`rename_function_by_address` and `create_function` ignore it and hit the active program; four binaries share the name `BOOT.BIN`; check `list_open_programs` first). `search_byte_patterns` ignores its `mask`. `rename_data` rejects this project's global names while `rename_function` only warns: do not rename to satisfy the validator ([ADR-0005](docs/architecture/adr/0005-ghidra-conventions.md)), use `create_label`. A duplicate address in `names.tsv` silently breaks `just apply-names` for the whole group.

**A boot chain watched on RPCS3 with savedata present is a different, shorter chain** (HD skipped `FirstPlay`: seven steps where `skin.xml` declares eight; only `Data BCES00664-AUTO- has been found` in `TTY.log` said so). Move the save aside before a boot-order capture (`just rpcs3-bootchain`, [hd-frontend.md](docs/formats/hd-frontend.md)): flipping a chain to `Measured` off such a log is [ADR-0025](docs/architecture/adr/0025-a-boot-chain-carries-its-provenance.md)'s error one level down.

**A `--screenshot --until` run over a movie leg on a machine with a real audio device fails with `never reached "X" in 3600 ticks` or captures an early frame**: a movie with sound is audio-clocked (ADR-0019). **Pass `--no-audio`** (null backend, tick-clocked movie).

**A live Ghidra function boundary can drift from what a `docs/` page records** (`mine.md`'s `0x08859ac8` decompiled to a different function; probably `just apply-names` not replayed): disassemble around a documented address before calling the finding wrong.

**PS3 TOC traps on `ps3-hdfury-eu`** ([toolchain.md](docs/reverse-engineering/toolchain.md#toc-traps-worth-remembering-moved-from-handovermd)): a decompile above the `0x32d5e0` TOC break names the wrong strings (`Shader_InitEngineParams` `0x003f1300`; fixed in place 2026-08-28, an earlier read not re-verified keeps the suspicion); `get_xrefs_to` for a TOC-relative load is only as good as the function's own TOC (check `scripts/ps3-toc.py toc <addr>` first; `0x008ad4d8` means trust it); an ELFv1 indirect call hides a real global behind an opaque `iStack_NNNN` (`Environment_LoadStageTextures` `0x003d6dc8`); and proximity to a known-good table is not evidence of relatedness.

**A stationary `--race` capture never reaches the particle path** (199 bytes of `psys` against 1.99 MB under `--autopilot --give rocket --press square`; an FSR 1 preference was carried for weeks on such a capture). Add `--give rocket --hold cross --press square` to any capture meant to judge effects, and prefer a play-test over a still for a picture-quality judgement.

**A menu or front-end capture taken with `--upscaler` is not evidence about the upscaler**: the flag changes the UPSCALER row's own text, and since [ADR-0038](docs/architecture/adr/0038-a-stage-with-no-scene-draws-at-presentation-resolution.md) no upscaler touches menu pixels. **Correction of record: ADR-0036's "every race `--screenshot` changes bytes when the HUD moves" is false (only `--presented` does)**; ADR-0038 supersedes its movie item. Do not re-baseline race screenshots on that sentence.

**`RemoteDebuggerOnStartup` does not pause the CPU at boot** (the first connection read `ticks: 22061009`, enough for a boot-time initializer to write before a watchpoint exists; `docs/ghidra/functions/psp-pulse-usa/collision.md`). If a watchpoint's "no writer" disagrees with a plainly non-default live read, suspect this and do a static instruction sweep.

**Two debugger connections racing the same PPSSPP breakpoint corrupt the read** (breakpoints are global CPU state; a garbage read of `0` was armed as a watchpoint on `0x30`). Bounds-check any computed watch address against `0x08000000`-`0x0A000000` ([`ppsspp-debugger.md`](docs/reverse-engineering/ppsspp-debugger.md#two-connections-racing-the-same-execution-breakpoint-corrupts-the-read-not-just-the-timing)).

**The `00000030` emulator halt** (`E[MEMMAP] Bad memory access detected! 00000030`) **is caused by writing the LeachBeam fire bit `0x8000` via `scripts/psp-fire-weapon.py`'s raw-bit mechanism**, not by a bad watchpoint. **Do not fire the LeachBeam that way** ([account](docs/ghidra/functions/psp-pulse-usa/bad-memory-access-halt.md)).

**RPCS3 gotchas** ([rpcs3-debugger.md](docs/reverse-engineering/rpcs3-debugger.md)): with no PS3 firmware a boot exits with `Firmware is missing` (firmware is the user's install); **`pgrep -x rpcs3` never matches** (the `comm` is `AppRun.wrapped`: check `/proc/<pid>` or `TTY.log` growth); the first-run "Welcome" dialog overlays every screenshot (`infoBoxEnabledWelcome=false` in `~/.config/rpcs3/GuiConfigs/CurrentSettings.ini`); **a `DISPLAY` export in one Bash call does not persist to the next**, so use `scripts/rpcs3-drive.py`'s `Session`. `EpilepsyWarning`'s live path needs a `cross` press (`Session.wait_for_screen_pressing`, [hd-frontend.md](docs/formats/hd-frontend.md#the-boot-chain-declared-and-then-watched)).

**A bit-exact comparison of the sideshift timer columns sees a tiny negative residue where a clamped port reads `0.0`; that is the original** (`Ship_UpdateSideshiftInput_q` at `0x08846a54`). `advance_sideshift` in `crates/physics/src/airbrake.rs` clamps with `.max(0.0)` deliberately (readers gate on `> 0.0`, and the fields feed `ShipState::hash_state`'s golden hashes) ([`input-bindings.md`](docs/ghidra/functions/psp-pulse-usa/input-bindings.md#the-countdown-does-not-clamp-at-zero-and-the-ports-does---deliberately-left-that-way)).

**A fragment `<LoadXML>` that never resolves is not always a missing file**: HD's `DATA05` `speedlap_hud.xml` disables `HUD_lap_ghost.xml` by misspelling the tag `<aLoadXML>` ([hd-hud.md](docs/formats/hd-hud.md)). If a composition lacks a feature a sibling copy has, check for a misspelled tag first.

**Reaching an arbitrary circuit through the front end is gated by Race Campaign progression**, not by anything `psp-drive.py` or the debugger can skip: RaceBox's Custom Race Track Select lists only the three `PI_Track` entries with no `<Unlock>` in `Data\Plugins\PI001\Definition.xml`; the rest carry `<Unlock Grid="N">` and a fresh profile has Grid 1 of 16. Check the target's `Grid` before planning a capture.

**A device test with a uniform depth buffer cannot exercise a depth-weighted term** (`post::motion_blur`'s test cleared depth to a flat `0.5` and a real bug hid). **Whatever a filter classifies by, the test must vary** (depth, velocity, material), else it tests the average, not the decision. **A reach cap that doubles as a tile size makes a square reduction starve the GPU** (the tell is a fullscreen pass whose target is much smaller than its source; [`motion-blur.md`](docs/rendering/motion-blur.md)).

**A worktree sharing `CARGO_TARGET_DIR` with the main checkout compiles against the other tree's uncommitted code**: never share it. `data/` does not travel into a worktree: `just link-data` (do not `rm -rf data`, `data/README.md` is tracked).

**A grid of eight identical craft is what an *empty* roster looks like**: `livery::teams_for_slots` fell back to the player's team when two faults each produced an empty team list; report the *reason*, not `0 team(s)`. HD ships its plugin definition **five times** with disagreeing copies ([hd-status.md](docs/formats/hd-status.md#it-ships-five-times-and-the-copies-disagree)) and at `Data\Plugins\Frontend\Definition.xml` (`oag_title::Title::plugin_definition`). `fexml::expand` refuses a file with no `<code>` dictionary: **a new `read_name` of an XML entry should be `fexml::text`, not `fexml::expand`, unless the file is known to be shortened**.

**A name-variant sweep is only as good as its extension list; when a whole class of names misses and the rest hit, the loader applies a transformation, not more spellings.** The PS2 texture resolver rewrites `.MIP` and `.TGA` to `.PCT` before hashing ([texture-names.md](docs/ghidra/functions/ps2-pulse-eu/texture-names.md), `oag_pulse::ps2_texture_name`). The sweep covered `read_name` call sites in `crates/game/src` and `crates/render/src` only: a PS2 asset gap phrased "not in the archive set" deserves the rewrite tried first.

**HD renderer, open or settled** ([renderer.md](docs/ghidra/functions/ps3-hdfury-eu/renderer.md)): draw order is answered (`RenderManager_CompareQueueKeys`, `0x002d4b58`). Open: which class each of the five producer sites belongs to, where `instance+0x11c` (the per-instance depth override) is written, the PS3 draw path itself (inline command-buffer writes; search for RSX method constants), and 62 of 124 engine shader `SHO` pairings.

**A model that reports the right triangle count can still render nothing: check the alpha test, not the class table** (Pure's `Speedup Pad`: `mesh.wgsl`'s invented `ALPHA_TEST_THRESHOLD` of `0.5` discarded a glow texture that tops out at alpha 58/255). `oag-view --pads --screenshot` or `crates/render/tests/pad_alpha_test_ground_truth.rs` is the check; the reference is per batch and read off the file (`docs/formats/vex.md`). **`GU_GREATER` reproduced as `<` is `GEQUAL`, and at reference `0` that is no alpha test**: a comparison that is exact either way on today's data is a latent bug, and a one-sided count cannot see a cutout that stopped cutting (that test captures the pad as authored and with the reference forced below any alpha).

**An ordering that holds on the mean and not on one run is the measurement being noisy, not the setting being broken** (`crates/raceplay/tests/difficulty_ground_truth.rs` averages five seeds and prints the spread).

**A synthetic race fixture has a horizon of `STALL_TICKS` (120)**: `race_with_a_grid` uses `Handling::ZERO`, so the stall rescue recovers all seven opponents and zeroes the throttle; a longer fixture needs handling that moves them.

**Subsystem traps have moved to their pages**: [surveying a disc](docs/formats/wad.md#traps-when-surveying-a-disc), [the Ghidra database versus `names.tsv`](docs/ghidra/workflow.md#the-database-can-disagree-with-namestsv-and-the-docs-win), [PPSSPP session hygiene](docs/reverse-engineering/ppsspp-debugger.md#session-hygiene), and the `ffmpeg`/`ffprobe`/GStreamer traps in [frontend-boot.md](docs/architecture/frontend-boot.md). What is left is this machine and this checkout:

- `data/` could be on `ecryptfs`: `cp --reflink` does not work and `ls`/`rg` intermittently fail on directories that exist; `fd`, `find` and absolute paths work. **`/tmp` is a 32 GB tmpfs**: extracting a large WAD into it once broke the shell; scan through `oag_assets::Archive` in memory.
- **Backticks in a justfile are command substitution at parse time**, even inside an `@echo` string (an echoed example once ran a full trace-compare on every `just`). **`XDG_CONFIG_HOME` points `oag-game` at a scratch `settings.toml`** for A/B config captures.
- **A niri screenshot piped through `wl-paste` can return the PREVIOUS clipboard image** (`psp-trace.py` writes `.stale.png` when it detects it); screenshots land in `~/Pictures/Screenshots/`. **Judge line width at native 480x272 only** (upscaling turns a one-pixel line into a magnification argument).
- **Shipped `section` data is not tidy and a strict parser refuses real tracks** (about 2 % of PVS mask bits name an undeclared section; benign, [`track.md`](docs/formats/track.md)).
- **No capture shows the BRIGHTNESS or GAMMA settings** (they apply at the blit, which `--screenshot` never reaches); the check is `upscale::tests::the_grade_moves_the_picture_in_the_direction_the_setting_names`, which **skips with a note where there is no adapter**, so a green CI run does not mean it ran.
- **`--features native-video` makes the boot fifty times slower and `just play` turns it on** (`GstDecoder::open` decodes every frame into memory; [ADR-0017](docs/architecture/adr/0017-gstreamer-native-video.md)). **Two things convert into `data/cache/movies` and must never overlap** (the boot's reels and the `--prefetch` worker; `Session::start_prefetch` serialises them). **An existing AV1 cache file beats the platform decoder with no flag**, and `--prefetch` sets `prefer_cache` unconditionally because the GStreamer path writes no cache file yet reports converted: timings and flags in [frontend-boot.md](docs/architecture/frontend-boot.md).
- **A display gate keyed on "is there data" reads "nobody reported" and "nothing to report" as the same thing**: the loading bar vanished because the media phase reported no counts; the bar must stay monotonic ([frontend boot](docs/architecture/frontend-boot.md#loading-is-not-transcoding)).

**`psp-pulse-usa`'s Ghidra DB stores every static address pre-relocation, so `get_xrefs_to` and `get_function_callers` return "none" for almost all `jal` targets**: `target = image_base + ((word & 0x03FFFFFF) << 2)` with image base `0x08804000`, so "no callers" is not evidence; use `search_instructions` on the zero-padded *relative* operand (`jal 0x000645cc`, not `jal 0x0886a5cc`; [contact-response.md](docs/ghidra/functions/psp-pulse-usa/contact-response.md#its-call-target-needed-the-image-base-added-by-hand---ghidras-own-bytes-are-pre-relocation), [weapon-fire.md](docs/ghidra/functions/psp-pulse-usa/weapon-fire.md#read-this-first-the-disassemblys-addresses-are-image-base-relative)). `psp-pulse-eu` has it too, which leans towards the importer; whether it is a PSP-ELF trait is open.

**The same pre-relocation values are in `lui`/`lw` HI16/LO16 pairs and raw data words, and the base is per segment** (`.data` gets `+0x08804000`; `.cplinit`/`.linkonce.d`/`.ctors`/`.bss` get `0x08ad9798`; [anim-transform.md](docs/ghidra/functions/psp-pulse-usa/anim-transform.md#the-second-relocation-base-is-found-it-is-per-segment-not-per-image)). **Do not do the arithmetic by hand: `scripts/psp-relocate.py` replays the PRX relocation records**, and an empty xref result proves nothing here (a `.rodata` string reference has no working xref at all): [workflow.md](docs/ghidra/workflow.md#stop-doing-it-by-hand-scriptspsp-relocatepy), [raw-binary scan](docs/ghidra/workflow.md#reading-the-raw-binary-outside-ghidra).

## Verification status: what to lean on

**The disc chooser was driven end to end on this machine** (2026-08-18; no automated way, and no headless capture reaches it). To repeat it, input must go over X11 (`unset WAYLAND_DISPLAY`; `xdotool key --window` does not work, so focus the window and use plain `xdotool key`); **Xvfb was no substitute on 2026-08-18** (Mesa reported "No DRI3 support detected" and nothing was drawn); **unsettled since**: other pages drive windowed `oag-game` under Xvfb on lavapipe (`docs/ui/endrace-screens.md`, `docs/networking/online-lobby.md`), and one `just launch` under `scripts/xvfb-own.sh` with `VK_ICD_FILENAMES=/usr/share/vulkan/icd.d/lvp_icd.json` would settle it for the chooser. Details: [menus.md](docs/architecture/menus.md#the-one-screen-that-is-not-a-menu).

**The cross-platform determinism gate** runs four layers (`oag-core`, `oag-physics`, `oag-gameplay`, an `oag-ai` scenario; Linux, Windows and macOS, release and debug); two mechanisms keep the hashed field list from rotting and **both are needed** (exhaustive destructuring makes a new `ShipState`/`Body` field a compile error, and a perturbation test proves each field reaches the hash). [determinism.md](docs/architecture/determinism.md#each-gate-covers-the-layer-below-it-and-one-thing-more) lists what is uncovered (maglock, reset, the swept tunnelling path).

**Measured against the original running** (method and numbers on their pages; lean on them, do not requote): the forward force law, lateral grip, the yaw accumulator, the inertia tensor on all three axes, the pitch step response, the contact friction coefficient, the mag-lock probe, the authored `Start Position` frame, and the chase camera (`crates/raceplay/tests/chase_camera_ground_truth.rs`): [`docs/physics/`](docs/physics/README.md). The whole-lap result has its limit: over the clean window position tracks to 6.54 units worst / 2.41 mean, nothing after tick 256 measures our physics against the current capture, and `grounded` is a constant column ([oag-trace.md](docs/tools/oag-trace.md#reseeding-and-why-a-long-comparison-needs-it)).

**Instruction-level reading with no runtime leg yet**: mag-lock's blend weights and its `|h - d| > 5.0` fallback, the swept collision path, everything airborne, both sideshift gestures. Single-sided wall rejection is measured against the *data* (2,076 of 2,084 wall triangles on `16_Track` wind toward the track's own spline).

**Two standing rules.** When the determinism test fails, find the bug; never update the reference constants. Never raise a confidence score because the simulation agrees with itself.
